# TRADING BOT

## The key idea

**Automated Trading Bot with Rule-Based Execution Engine**

This project is a comprehensive trading automation platform that allows users to create, manage, and execute complex trading strategies through a visual rule-based system. The core innovation lies in its modular action architecture that enables users to build sophisticated trading workflows without coding.

## Project description

This project aims to provide a highly flexible and configurable trading automation platform. At its core, the platform enables users to define their own trading strategies and workflows using a JSON-based Domain Specific Language (DSL). This approach allows users to combine a wide variety of pre-built configuration "chunks"—such as intervals, timeouts, conditions, notifiers, order execution, and price checkers—into custom rule sets tailored to their needs.

For example, a user could create a rule like: "Every day, check the price of BTCUSDT trading pair. If the price has been consistently increasing for 10 days, send me a notification on Telegram with text 'BTCUSDT grows for 10 days'."

Key features of the platform include:
- A modular, JSON-based configuration system that empowers users to build complex trading logic without coding.
- Integration with external APIs to gather necessary trading data.
- The ability to collect, store, and process information as needed.
- Event triggering and workflow execution based on user-defined JSON configurations.
- Multi-user support, allowing each user to manage their own independent set of trading rules.

In summary, the platform is designed to be a powerful, and extensible solution for automated trading(or treading helper), adaptable to a wide range of strategies and requirements.

## Project Overview

### What We're Building
The Trading Bot is an automated trading platform that allows users to create, manage, and execute complex trading strategies through a visual rule-based system. Users can build sophisticated trading workflows without coding using our JSON-based Domain Specific Language (DSL).

### Key Features
- **Rule-Based Trading Engine**: Create trading strategies using JSON configurations
- **Modular Action Architecture**: Combine pre-built components (intervals, conditions, notifications, etc.)
- **Multi-User Support**: Each user manages their own independent trading rules
- **External API Integration**: Connect with trading platforms and data sources
- **Real-time Execution**: Automated workflow execution based on user-defined rules

### Example Use Case
*"Every day, check the price of BTCUSDT trading pair. If the price has been consistently increasing for 10 days, send me a notification on Telegram with text 'BTCUSDT grows for 10 days'."*

## Architecture

### Technology Stack
- **Monorepo Management**: NX
- **Backend**: NestJS (Node.js/TypeScript)
- **Frontend**: React with Chakra UI
- **Database**: PostgreSQL with Prisma ORM
- **Containerization**: Docker
- **Package Manager**: pnpm
- **CI/CD**: GitHub Actions

### Project Structure
```
trading-bot/
├── apps/
│   ├── api/                    # NestJS backend API
│   ├── auto-trader/            # Trading execution engine
│   └── user-control-panel/     # React frontend
├── libs/
│   ├── models/                 # Database models & Prisma
│   ├── configs/                 # Shared configurations
│   └── object-navigator/        # Utility library
├── docs/                        # Documentation
└── scripts/                     # Development scripts
```

### Microservices Architecture
1. **API Service** (`apps/api/`): REST API for user management and rule CRUD operations
2. **Auto Trader** (`apps/auto-trader/`): Core trading engine that executes user rules
3. **User Control Panel** (`apps/user-control-panel/`): React frontend for rule management

### Data Flow
1. Users create trading rules via the frontend
2. Rules are stored in PostgreSQL via the API
3. Auto Trader reads rules and executes trading logic
4. External APIs provide market data
5. Notifications sent via Telegram/other channels

## Development Workflow

### Getting Started
1. Follow the [First Time Setup Guide](./first-time-set-up-for-development.md)
2. Verify your environment with `./scripts/dev-tools-checking.sh`
3. Run all services: `pnpm all:start`

### Daily Development
```bash

pnpm all:start

# Run tests
pnpm all:test

# Run linting
pnpm all:lint

# Build all apps
pnpm all:build
```

### Branch Strategy
- **main**: Production-ready code
- **develop**: Integration branch for features
- **feature/***: Feature development branches
- **hotfix/***: Critical bug fixes

### Commit Convention
```
type(scope): description

feat(api): add user authentication endpoint
fix(frontend): resolve routing issue in rules page
docs(readme): update setup instructions
```

Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`
